## 0.1.0-preview.2 - 2026-09-23

### Added

- Add Alpine (musl) binaries and installer support for `linux-musl-x64` and `linux-musl-arm64`. ([#242](https://github.com/goldbarth/chartula/pull/242))
- Add `faithfulness.model` and `faithfulness.thinking` to configure the thorough check independently of `llm`. ([#232](https://github.com/goldbarth/chartula/pull/232))
- Add release scope metrics for commits, pull requests, facts, and fact description length to the run summary and record. ([#231](https://github.com/goldbarth/chartula/pull/231))
- Add cached input and reasoning output token counts to the run summary and record. ([#230](https://github.com/goldbarth/chartula/pull/230))
- Add model-call durations and retry counts to run metrics. ([#229](https://github.com/goldbarth/chartula/pull/229))
- Add provider-neutral reasoning levels through `llm.thinking`. ([#228](https://github.com/goldbarth/chartula/pull/228))
- Add a local JSON run record for each `generate` run. ([#227](https://github.com/goldbarth/chartula/pull/227))
- Add `thinking`, `thoroughCheck`, and `factBaseDepth` to `changelog.json` provenance. ([#225](https://github.com/goldbarth/chartula/pull/225))
- Add one-command installation on Linux, macOS, and Windows through `install.sh` and `install.ps1`. ([#214](https://github.com/goldbarth/chartula/pull/214))

### Fixed

- Fix shallow-clone handling to refuse release history that cannot be read completely without a usable `--since` reference. ([#244](https://github.com/goldbarth/chartula/pull/244))
- Remove the ICU runtime requirement from Linux binaries by enabling invariant globalization. ([#241](https://github.com/goldbarth/chartula/pull/241))
- Fix `chartula.yaml` validation to report malformed configuration with file, line, and column. ([#238](https://github.com/goldbarth/chartula/pull/238))
- Fix model-call errors to identify the provider, endpoint, model, and response status. ([#236](https://github.com/goldbarth/chartula/pull/236))
- Fix configuration validation to refuse `Chartula__Llm__BaseUrl` when its host belongs to another provider's API. ([#235](https://github.com/goldbarth/chartula/pull/235))
- Fix publication failures to report the refusal alongside files already written by the run. ([#221](https://github.com/goldbarth/chartula/pull/221))
- Fix missing-tag errors to identify the checkout and its available tags. ([#220](https://github.com/goldbarth/chartula/pull/220))
- Fix GitHub access errors to identify the repository and whether a token was sent. ([#218](https://github.com/goldbarth/chartula/pull/218))

## 0.1.0-preview.1 - 2026-09-17

### Added

- Refuse the adaptive and disabled thinking-mode combinations that the Anthropic API rejects at configuration load, rather than failing only on the first request. ([#133](https://github.com/goldbarth/chartula/pull/133))
- Move the structure of every rendering out of the prompt and into code, so the model only writes the wording of each entry. ([#129](https://github.com/goldbarth/chartula/pull/129))
- Align the technical, customer and product prompts with their finished templates and rubrics, deciding template-level structure when the facts are built rather than in the prompt. ([#126](https://github.com/goldbarth/chartula/pull/126))
- Carry the labels of a change into the fact base and into changelog.json. ([#120](https://github.com/goldbarth/chartula/pull/120))
- Add an --audience option so a run renders only the named audiences instead of all three. ([#116](https://github.com/goldbarth/chartula/pull/116))
- Carry four missing customer format rules into the prompt: ordering actionable entries above others, ending on the last group rather than a closing line, collapsing non-actionable changes into one 'Also:' bullet, and requiring a checkable basis for any claim of degree. ([#112](https://github.com/goldbarth/chartula/pull/112))
- Warn at startup on stderr when a run has no GitHub token, explaining the lower rate limit and how to set one. ([#110](https://github.com/goldbarth/chartula/pull/110))
- Write the customer rendering as a publishable release-<tag>.md page with YAML front matter. ([#104](https://github.com/goldbarth/chartula/pull/104))
- Add a --no-publish flag that writes changelog.json and CHANGELOG.md while leaving the GitHub release notes unpublished. ([#101](https://github.com/goldbarth/chartula/pull/101))
- Add an openai-compatible LLM provider with a configurable base URL, reaching any endpoint that speaks the OpenAI chat-completions dialect. ([#88](https://github.com/goldbarth/chartula/pull/88))
- Add an llm.thinking configuration setting with provider-default, disabled and adaptive modes. ([#83](https://github.com/goldbarth/chartula/pull/83))
- Report each run's token usage and cost, broken down by rule-based check, thorough check and rephrasing. ([#66](https://github.com/goldbarth/chartula/pull/66))
- Add a categories configuration section for category order, display names and breaking-change prominence. ([#65](https://github.com/goldbarth/chartula/pull/65))
- Read chartula.yaml for configuration, with sensible defaults when no file is present. ([#64](https://github.com/goldbarth/chartula/pull/64))
- Add generate and preview CLI commands wired to the release pipeline. ([#63](https://github.com/goldbarth/chartula/pull/63))
- Store the technical, customer and product renderings in changelog.json. ([#62](https://github.com/goldbarth/chartula/pull/62))
- Write the generated technical text back to the release's GitHub release notes, updating rather than duplicating on a re-run. ([#61](https://github.com/goldbarth/chartula/pull/61))

- Add an opt-in review mode that lets a maintainer approve or edit generated text before it is written. ([#59](https://github.com/goldbarth/chartula/pull/59))
- Add a thorough, LLM-based second-pass faithfulness check, on by default and toggled by a single setting. ([#58](https://github.com/goldbarth/chartula/pull/58))
- Add a rule-based faithfulness check that flags invented numbers, names and breaking-change claims at no token cost. ([#57](https://github.com/goldbarth/chartula/pull/57))
- Normalize formatting and enforce a single consistent voice across each audience's rendering. ([#56](https://github.com/goldbarth/chartula/pull/56))
- Render technical, customer and product audiences from one shared fact base, so they cannot contradict each other. ([#55](https://github.com/goldbarth/chartula/pull/55))
- Add a prompt architecture that rephrases only the established facts it is given, never inventing beyond them. ([#53](https://github.com/goldbarth/chartula/pull/53))
- Generate a changelog through the provider interface, making exactly one model call per release. ([#52](https://github.com/goldbarth/chartula/pull/52))
- Write the release fact base to changelog.json as a stable, versioned, machine-readable record. ([#51](https://github.com/goldbarth/chartula/pull/51))

- Add label rules that can exclude a change, force its category, or restrict the changelog to labelled changes only, driven from configuration. ([#46](https://github.com/goldbarth/chartula/pull/46))
